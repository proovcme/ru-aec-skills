# Установка и подключение

Выберите **приложение**, а не только название модели. Claude Code и чат Claude, Gemini CLI и чат Gemini, Qwen Code и модель Qwen в другом клиенте имеют разные способы подключения инструкций.

## Подготовка для всех вариантов

1. Скачайте **Code → Download ZIP** со страницы репозитория и распакуйте его либо выполните:

   ```sh
   git clone https://github.com/proovcme/ru-aec-skills.git
   ```

2. Папки верхнего уровня с `SKILL.md` — 44 отдельных скилла. Сохраните их названия и всё содержимое, включая `references` и необязательный `agents`.
3. Общие процедуры находятся в соседних скиллах. Для нативной установки переносите полный комплект рядом. При выборочной установке проверьте всю цепочку относительных ссылок, включая ссылки общих процедур.
4. Если одноимённые скиллы уже установлены, сравните версии и сохраните собственные изменения до замены. Не копируйте `.git` в каталог скиллов.

## Нативная установка в агенты

`~` означает домашнюю папку пользователя, а проектный путь отсчитывается от корня вашего проекта. Копируйте **папки скиллов непосредственно в указанный каталог**, без дополнительного уровня `ru-aec-skills`.

| Приложение | Для одного проекта | Для пользователя | Как проверить доступность |
| --- | --- | --- | --- |
| Codex | `.agents/skills/` | Через встроенный `skill-installer` | Список скиллов интерфейса; в CLI/IDE — `/skills` или выбор через `$` |
| Claude Code | `.claude/skills/` | `~/.claude/skills/` | Вызов `/aec-review-design-usability` |
| Gemini CLI | `.gemini/skills/` | `~/.gemini/skills/` | `/skills reload`, затем `/skills list` |
| Qwen Code | `.qwen/skills/` | `~/.qwen/skills/` | `/skills`, затем выбор нужного скилла |
| Antigravity | `.agents/skills/` | `~/.gemini/config/skills/` | Новая беседа в проекте и применение скилла по имени |

Например, для Claude Code корректен путь `.claude/skills/hvac-define-design-basis/SKILL.md`. Путь `.claude/skills/ru-aec-skills/hvac-define-design-basis/SKILL.md` для этого способа не используйте.

### Codex

Для проектной установки скопируйте все 44 папки в `.agents/skills/`. Для персональной можно поручить встроенному установщику:

```text
$skill-installer Установи все папки с SKILL.md из
https://github.com/proovcme/ru-aec-skills
как отдельные соседние скиллы вместе с их ресурсами.
При существующих одноимённых папках остановись и покажи конфликты.
```

Вызовите нужный скилл через селектор или упомяните его явно в поддерживаемом интерфейсе:

```text
$hvac-calculate-room-airflows Проверь воздушный баланс по таблице.
Отдели допущения от подтверждённых данных. Файлы пока не изменяй.
```

Если скиллы не появились, перезапустите клиент. Каталог персональной установки зависит от версии установщика; не создавайте вторую копию поверх уже обнаруживаемой. [Документация Codex](https://learn.chatgpt.com/docs/build-skills).

### Claude Code

Скопируйте комплект в `.claude/skills/` проекта либо в `~/.claude/skills/`. Откройте проект в Claude Code и вызовите:

```text
/aec-review-design-usability Проверь двери и проходы по приложенному плану.
Не изменяй модель, сначала покажи измерения и замечания.
```

Если каталог скиллов создан впервые и не обнаружен, перезапустите Claude Code. Ресурсы должны оставаться доступны по относительным путям. [Документация Claude Code](https://code.claude.com/docs/en/skills).

### Gemini CLI

Скопируйте комплект в `.gemini/skills/` проекта либо в `~/.gemini/skills/`. Затем выполните в сессии:

```text
/skills reload
/skills list
```

Попросите применить нужный скилл по имени к конкретной задаче. Gemini CLI также поддерживает `.agents/skills/` как альтернативный каталог; не дублируйте там другую версию того же комплекта. [Документация Gemini CLI](https://geminicli.com/docs/cli/skills/).

### Qwen Code

Скопируйте комплект в `.qwen/skills/` проекта либо в `~/.qwen/skills/`. Откройте `/skills`, выберите нужный скилл и задайте задачу с исходными данными. Если список не обновился, начните новую сессию. Не используйте генерацию нового скилла из текста вместо установки существующих папок: она может изменить содержание. [Документация Qwen Code](https://qwenlm.github.io/qwen-code-docs/en/users/features/skills/).

### Antigravity

Скопируйте все 44 папки в `.agents/skills/` открытого проекта либо в `~/.gemini/config/skills/` для всех проектов. Например: `.agents/skills/hvac-coordinate-bim/SKILL.md`. Начните новую беседу и попросите:

```text
Примени скилл hvac-coordinate-bim к приложенному фрагменту модели.
Сначала прочитай SKILL.md и необходимые references.
Проверь связность, монтажную пригодность и обслуживание, без изменений.
```

Убедитесь, что агент нашёл именно установленную версию и прочитал ресурсы по фактическим путям. В актуальной документации основной проектный каталог — `.agents/skills/`; `.agent/skills/` сохраняется для обратной совместимости. Не создавайте дубликаты в обоих. Для старой версии или отдельного IDE/CLI-клиента сверьте её настройки с [официальной документацией Antigravity](https://antigravity.google/docs/skills).

## Claude Desktop

### Импорт через Skills

Если в вашей версии приложения и аккаунте доступен раздел **Customize → Skills**, используйте импорт скилла через ZIP. При необходимости включите **Code execution and file creation** в **Settings → Capabilities**; в организации доступ может регулировать администратор.

1. Подготовьте **самодостаточную копию выбранного скилла** по инструкции ниже. Не загружайте ZIP всего репозитория как один скилл.
2. Упакуйте папку этой копии в ZIP.
3. Откройте **Customize → Skills → + → Create skill → Upload a skill**, загрузите архив и включите скилл.
4. Начните задачу с явным указанием имени скилла. Проверьте чтение необходимых ресурсов, а не только появление в списке.

Папки `.claude/skills` относятся к Claude Code и не заменяют этот импорт. Если нужного экрана в Desktop нет, проверьте его в веб-интерфейсе того же аккаунта или используйте ручной режим ниже. [Официальный порядок импорта Skills в Claude](https://support.claude.com/en/articles/12512180-use-skills-in-claude).

### Подготовка самодостаточного ZIP

Скиллы этого репозитория используют соседние папки. При отдельном импорте нельзя рассчитывать на сохранение такого соседства. **Один архив исходной папки без зависимостей недостаточен.**

В отдельной копии, не меняя оригиналы:

1. Оставьте выбранный `SKILL.md` и его собственные ресурсы.
2. Проследите все локальные ссылки и перенесите недостающие документы из соседних скиллов внутрь копии, например в `references/shared/<имя-скилла>/...`. Сохраните различимые имена и происхождение файлов.
3. Перепишите относительные ссылки в копии так, чтобы они вели к новым внутренним путям. Проверьте также ссылки внутри перенесённых документов и текстовые инструкции о соседних файлах. Не сокращайте нормативные условия и не превращайте условные references в обязательное чтение всех файлов.
4. Убедитесь, что каждый необходимый файл доступен внутри папки, затем архивируйте её. При обновлении исходного комплекта пересобирайте эту копию.

Альтернатива без переупаковки: передайте выбранный `SKILL.md` и полные тексты нужных references в разговор, явно назначив их инструкциями для задачи по ручному режиму ниже. Это не нативный импорт.

## Qwen Desktop

### Настольный чат Qwen / Qwen Studio

Не переносите каталог `.qwen/skills` из инструкции Qwen Code в обычный настольный чат: механизм загрузки определяется приложением. Официальную сборку выбирайте на [странице загрузки Qwen](https://qwen.ai/download).

Для подключения без привязки к неподтверждённому интерфейсу импорта:

1. Создайте отдельный разговор нужного профиля.
2. Первым сообщением передайте содержательную часть выбранного `SKILL.md` и формулировку ручного подключения ниже. Если ваша версия предоставляет постоянные инструкции проекта/ассистента, их можно сохранить там.
3. Передайте полные тексты необходимых references отдельными блоками с исходными путями или доступными в вашей версии вложениями. Для гарантированного текстового пути можно вставить содержимое прямо в сообщение.
4. Попросите применить процедуру к конкретным исходным данным. Если текст не помещается, сузьте задачу и набор условных references; не убирайте влияющие требования.

Это ручное подключение инструкций. Наличие модели Qwen, доступа к файлам или кнопки вложения само по себе не подтверждает автоматическую загрузку Agent Skills.

### Если имеется в виду Qwen Code Desktop

Это отдельный продукт линейки Qwen Code. Откройте в нём проект с комплектом в `.qwen/skills/` и проверьте доступность скиллов в интерфейсе вашей версии; используйте раздел Qwen Code выше как описание структуры файлов. Не переносите команды CLI в поле обычного чата без поддержки команд интерфейсом. [Обновления Qwen Code, включая Desktop](https://qwenlm.github.io/qwen-code-docs/en/blog/updates/).

## Cherry Studio



Для обычного чата используйте **отдельного ассистента с выбранными инструкциями**, а не импорт всего репозитория как одного плагина.

1. Создайте ассистента нужного профиля, например «Проверка ОВ». Выберите доступную вам модель.
2. В поле системного промпта/инструкций ассистента перенесите содержательную часть одного нужного `SKILL.md` без YAML-шапки. Сохраните свой существующий промпт перед заменой или создайте нового ассистента.
3. Для текущей задачи передайте полностью требуемые этим скиллом reference-файлы: текстом в инструкции/сообщение либо через доступный клиенту механизм полного чтения файлов. При плоских вложениях обозначьте каждый текст исходным относительным путём.
4. Добавьте формулировку из раздела «Режим ручного подключения» ниже. Если reference недоступен, приложите его самостоятельно, а не рассчитывайте на переход по локальной Markdown-ссылке.
5. Начните новый разговор с конкретной задачей и проверьте, какие инструкции реально прочитаны. Не вставляйте все 44 скилла в системный промпт.

Названия экранов зависят от версии. Если используете отдельный агентный режим с поддержкой Agent Skills, устанавливайте по документации именно этого режима; обычный чат и агентный режим не следует считать одинаковыми. [Документация Cherry Studio](https://docs.cherry-ai.com/).

## AnythingLLM

Здесь можно подключить выбранную процедуру через **System Prompt рабочего пространства**. Это не установка исполняемого Custom Agent Skill AnythingLLM.

1. Создайте отдельное рабочее пространство для нужной дисциплины или задачи.
2. В его System Prompt добавьте содержательную часть выбранного `SKILL.md` и формулировку ручного подключения ниже. Сохраните предыдущие настройки перед изменением.
3. Дайте модели полные тексты необходимых references. Для небольшого набора вставьте их в инструкции или сообщение с обозначением исходных путей; при использовании документов или файловых инструментов проверьте получение полного текста.
4. Базу знаний можно использовать для поиска материалов, но одна загрузка в RAG не гарантирует, что все обязательные инструкции попадут в контекст. Ключевую процедуру держите в инструкциях, а обязательные references передавайте полностью для текущей задачи.
5. Для действий с файлами и приложениями отдельно настройте доступные инструменты и разрешения. Текст процедуры не создаёт файловый инструмент или связь с Revit.

В AnythingLLM собственные Custom Agent Skills имеют программный формат с `plugin.json` и обработчиком; папка с одним `SKILL.md` его не заменяет. См. [System Prompt](https://docs.anythingllm.com/features/system-prompt-variables) и [Custom Agent Skills](https://docs.anythingllm.com/agent/custom/introduction).

## Другие клиенты и обычные чаты

Если клиент поддерживает Agent Skills, следуйте его документации по каталогам, импорту и правам чтения соседних ресурсов. Не предполагайте, что ZIP всего репозитория можно загрузить как один скилл. Изолирующему каждый скилл клиенту понадобится адаптация общих зависимостей.

Для чатов Claude, Gemini, Qwen и других моделей без доступного файлового механизма используйте ручной режим: один нужный скилл как инструкции, полностью приложенные относящиеся references и конкретная задача. Это подключение процедуры к разговору, а не нативная установка с автоматическим выбором скиллов.

### Режим ручного подключения

Добавьте к выбранным инструкциям:

```text
Используй приложенную процедуру для поставленной задачи.
Сначала прочитай её целиком, затем необходимые по условиям references.
Назови прочитанные файлы по исходным путям. Если нужного текста нет,
запроси его и не подменяй выдуманной инструкцией.
Выполняй только запрошенную задачу и зависимые проверки.
Отличай нормативный вывод от арифметики и предварительных допущений.
Не утверждай, что проверил или изменил модель, если доступа к ней нет.
```

Названный моделью файл — не самостоятельное доказательство чтения. Сверьте ответ с конкретными требованиями процедуры. Если клиент обрезал текст из-за лимита контекста, сократите задачу, а не обязательные условия проверки.

## Обновление и контроль установки

- Получайте обновление в отдельную папку и сравнивайте с установленным комплектом. Сохраняйте собственные изменения до замены.
- Фиксируйте SHA версии: в клоне репозитория выполните `git rev-parse HEAD`.
- При копировании обновляйте согласованно связанные скиллы. При ручном режиме обновите также сохранённые промпты и вложенные references.
- Проверьте структуру каталогов, наличие выбранного скилла, чтение ресурсов и выполнение короткой задачи без опасных изменений. Сообщение «установлено» не заменяет эту проверку.
- Не выдавайте клиенту доступ ко всему диску или рабочей BIM-модели только ради установки текстовых инструкций.
