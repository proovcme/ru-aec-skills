# Выпуск ПБ и ЭОМ

## Масштаб работы
Локальный вопрос решай по относящимся входам; не запускай полный раздел и не создавай пустые реестры. Аудит не разрешает менять модель. Допущения допустимы для концепции, но не заменяют подтверждение для строительства. Выдай результат, проверку и оставшиеся ограничения.

- Разделяй ПД и РД, содержание мероприятий ПБ и рабочие комплекты отдельных систем; обозначения комплектов не выдумывай по названию скилла.
- Для состава ПД, СПДС и ТИМ используй [проектную документацию](../aec-develop-rf-design-documentation/SKILL.md) только по нужному маршруту. Для оценки готовности по предоставленным фактам достаточно [короткой проверки](../aec-develop-rf-design-documentation/references/release-triage.md).
- Для нормативных требований раздела выбери [ПБ](../fire-define-design-basis/references/normative-route.md) или [ЭОМ](../electrical-define-design-basis/references/normative-route.md), не оба автоматически.
- Сверь расчёты, модель, планы, схемы, марки/адреса, таблицы цепей и спецификации на одной согласованной ревизии. ПБ: границы зон/отсеков и алгоритмы; ЭОМ: источник, щит, нагрузка, кабель и защита.
- По каждой применимой форме проверь реальный номер, графы, заполнение и примечания по тексту стандарта; похожая таблица не означает соответствие. После выпуска просмотри листы: марки, размеры, отметки, привязки, читаемость и взаимные ссылки.
- Проверка проекта не равна пусконаладке. Не создавай фиктивные протоколы испытаний/согласования. Для строительства закрой зависимые проверки; для координации обозначь открытые вопросы и ограничения.
Выход: затронутый комплект, ведомость ревизий и доказательства проверок со статусом назначения выпуска. Отправка внешним участникам требует соответствующего поручения.
