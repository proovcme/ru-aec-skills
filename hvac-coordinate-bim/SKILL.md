# BIM-координация ОВ

Выполняй только запрошенный объём и зависимые проверки; требуй влияющие входы. Аудит не разрешает изменения. Вывод по описанию не означает проверку файлов.

Для задач РФ нормативный вывод подтверждай пунктом, применимой редакцией и проверкой. При установлении нормативной основы или подтверждении соответствия прочитай [общий протокол](../aec-govern-rf-capital-project/references/normative-workflow.md). Для расчёта по заданным данным или выявления явного противоречия полный нормативный аудит не нужен; нормативную допустимость при этом не объявляй.

Для короткой оценки по описанию достаточно установить конкретный дефект/непроверенные данные и границы вывода; связность портов не доказывает готовность системы. При фактическом моделировании или проверке модели прочитай [методику](references/method.md) полностью и выполни зависимые проверки.

## Полный цикл — для локальной задачи только зависимые пункты

1. Зафиксируй координаты, уровни, стадии, классификатор, имена систем, LOD/LOI и зоны ответственности.
2. Моделируй по зависимости: помещения → оборудование → магистрали → ответвления → терминалы/приборы → арматура и автоматика.
3. Перенеси в модель расходы, мощности, температуры, давления, сечения, огнестойкость и расчётные идентификаторы.
4. Создай сервисные зоны и монтажные ограничения.
5. Выдай задания АР, КР, ВК, ЭОМ, АВТ и пожарной автоматике с координатами, габаритами, требованиями и статусами.
6. Решай коллизии по физическим приоритетам и фиксируй влияние каждого изменения на расчёт.
7. Выполни проверку модели перед выпуском.

## Контроль

- Не использовать фиктивный размер элемента в координационной модели.
- Не перемещать расчётную ветвь без проверки давления/баланса.
- Не считать связанный коннектор доказательством правильной системы и параметров.
- При сборке воздуховодов обязательно применять монтажные проверки из раздела «Монтажная геометрия» в references/method.md; перед размножением проверить один узел после сохранения модели.

## Результат

Для локальной задачи — только затронутые результаты, допущения и проверка, без пустых/повторных реестров. Для полного цикла:

Выдай реестр систем, задания смежникам, журнал коллизий, отчёт проверки модели и список изменений для пересчёта.
