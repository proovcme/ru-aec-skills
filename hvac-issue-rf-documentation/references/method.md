# Методика выпуска ПД и РД ОВ

Для управления исходниками, заданиями, ревизиями и выдачей прочитай полностью [рабочий процесс документов](../../aec-develop-rf-design-documentation/references/document-workflow.md). Используй его реестры совместно с реестрами проекта, не дублируй их.

## Нормативная карта выпуска

Перед выдачей проверяй действующие редакции:

- Положения о составе разделов проектной документации, утверждённого Правительством РФ;
- ГОСТ 21.602-2016 для рабочих чертежей отопления, вентиляции и кондиционирования;
- ГОСТ 21.110-2013 для спецификаций;
- требований к электронным документам конкретной экспертизы/заказчика;
- проектной нормативной карты по расчётам и пожарной безопасности.

Не фиксируй состав тома только по старому шаблону: договор, стадия и принимающая организация могут требовать иной набор.

## Стадия П

Сформируй доказательную цепочку:

`исходные данные → нормативные критерии → расчётные параметры → принципиальные решения → нагрузки/ресурсы → пожарные и энергетические мероприятия → графические схемы → приложения`.

Текстовая и графическая части должны иметь одинаковые системы, расходы, нагрузки, источники и границы. Приложи расчётные материалы в объёме договора/экспертизы и обеспечь их трассируемость.

## Рабочая документация

Проверь наличие применимых общих данных, планов, разрезов/фрагментов, схем, узлов, заданий смежникам, спецификаций и требований к монтажу/испытаниям. Показывай только ту детализацию, которая нужна для однозначного выполнения и соответствует модели.

## Перекрёстная проверка

Для каждой системы сравни:

- расчётный расход/мощность ↔ марка на плане и схеме;
- размер сети ↔ расчёт и модель;
- оборудование ↔ опросный лист и спецификация;
- питание/автоматика/дренаж ↔ задания смежникам;
- противопожарное исполнение ↔ пожарная концепция и матрица причинно-следственных связей;
- количества ↔ ведомости модели и правила учёта.

## Управление изменениями

Зафиксируй основание, затронутые расчёты, модели, листы, спецификации и задания. Не выпускай изменение одного представления без проверки всей цепочки зависимостей.
