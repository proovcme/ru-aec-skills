# Plumbing Design Deliverables

Для короткой оценки готовности по описанию прочитай только [предварительную проверку](../aec-develop-rf-design-documentation/references/release-triage.md) и используй её вместо полного порядка ниже. Для фактического выпуска, работы с файлами или нормативного заключения выполняй полный применимый маршрут.

Выполняй только запрошенный объём и зависимые проверки; требуй влияющие входы. Аудит не разрешает изменения. Вывод по описанию не означает проверку файлов.

Для задач РФ нормативный вывод подтверждай пунктом, применимой редакцией и проверкой. При установлении нормативной основы или подтверждении соответствия прочитай [общий протокол](../aec-govern-rf-capital-project/references/normative-workflow.md). Для расчёта по заданным данным или выявления явного противоречия полный нормативный аудит не нужен; нормативную допустимость при этом не объявляй.

Выпускай согласованный пакет, где расчёты, модель, чертежи и спецификации описывают одну версию решения.

Для исполнительной документации прочитай [порядок исполнительных записей](../aec-manage-rf-executive-records/SKILL.md): нужны подтверждённые фактические работы, измерения и испытания. Проектная модель или переименованный комплект РД не подтверждают построенное состояние.

Для задач в РФ прочитай полностью [рабочий процесс документов](../aec-develop-rf-design-documentation/references/document-workflow.md): приём исходников, задания смежникам, ревизии и условия выдачи. Это общая зависимость установленного комплекта; не называй внутренние реестры нормативными формами.

## Полный цикл — для локальной задачи только зависимые пункты

1. Определи состав по договору, стадии, юрисдикции и требованиям принимающей стороны. Веди issue register с ответственными и статусами.
2. Собери цепочку доказательств: исходные данные → расходы и баланс → схемы → гидравлика → подбор → BIM → графика → спецификации.
3. Подготовь планы, схемы стояков/аксонометрии и необходимые профили. Покажи границы, направления, уклоны, отметки, диаметры, материалы, арматуру, оборудование и точки подключения в детализации стадии.
4. Сформируй текстовую часть как обоснование систем, расчётных случаев, водного баланса, давления, очистки/защиты, энергоэффективности, пожарных решений и эксплуатации.
5. Получай ведомости из контролируемых модельных данных или сверенного расчётного источника. Отделяй оборудование, трубы, фасонные части, изоляцию, арматуру и монтажные позиции по правилам проекта.
6. Проведи cross-check: все системы и элементы согласованы между расчётом, планом, схемой, спецификацией и заданиями; расходы и нагрузки не меняют смысл между таблицами.
7. Зафиксируй ревизию, изменения, открытые риски, исключения, перечень файлов и требуемые действия после выпуска.

## Release gate

Не подтверждай готовность пакета к строительству при неувязанных отметках самотёка, неподтверждённом давлении, критических расхождениях расчёта и модели либо незакрытых safety-critical интерфейсах.

## Результат

Для локальной задачи — только затронутые результаты, допущения и проверка, без пустых/повторных реестров. Для полного цикла:

Выдай issue register, QC-checklist, перечень файлов, журнал изменений, допущения, исключения и открытые действия.
