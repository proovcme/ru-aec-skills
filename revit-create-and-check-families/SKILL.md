# Семейства Revit: создание и приёмка

## Выбрать объём

Для объяснения или локального дефекта проверяй только зависимое поведение, без полного паспорта и обхода всех ссылок. Аудит не разрешает менять семейство. При создании/адаптации установи целевую версию Revit, категорию, основу и назначение; системный тип не подменяй загружаемым RFA ради удобства автоматизации.

Ресурсы читать только по задаче:

- Геометрия, параметрический каркас, условная графика и производительность: [геометрия](references/geometry.md).
- Марки, спецификации, общие параметры, вложенность и замена библиотечного семейства: [данные](references/data.md).
- Инженерные порты и поведение в сети: [соединители](references/mep.md).
- Семейства по каталогу производителя, таблицы поиска, вложенное УГО и выпуск каталога RVT/RTE: [библиотека инженерных семейств](references/vendor-catalog.md).
- Приёмка по уровням L0–L8, акт, дисциплина вызова Revit: [проверка](references/acceptance.md).
- Границы технической проверки и нормативного заключения: [применимость](references/applicability.md), только при оценке соответствия.

## Создать или исправить

1. Зафиксируй нужное поведение: реальные габариты/интерфейсы, переменные и допустимые диапазоны, точка вставки, основа, необходимые виды и выходные данные. Не выдумывай паспорт производителя; обобщённое семейство помечай как предварительное. У каждой строки размеров должен быть источник: ревизия каталога, страница, фрагмент.
2. Сделай минимальный параметрический прототип и проверь изменение размеров до детализации. Добавляй только функционально нужную геометрию и параметры.
3. Проверь затронутые зависимости в редакторе и тестовом проекте. Красивое 3D не доказывает работоспособность размеров, марок, ведомостей или сети.
4. До замены используемого RFA/семейства в проекте сохрани восстановимую версию. Испытай один экземпляр и перезагрузку на копии; не перезаписывай массово значения параметров проекта по умолчанию.

Работай через реально доступный поддерживаемый интерфейс Revit. Наличие скрипта или созданного файла не доказывает выполнение в Revit; без среды исполнения выдай подготовленный код/ТЗ и непроведённые проверки. Не имитируй RFA переименованным файлом.

## Сборка через API/MCP (движок без редактора)

Семейство можно собирать без интерактивного редактора: Revit запущен и служит движком, файлы в интерфейсе не открываются. Это допустимый путь, но он меняет доказательства — «видел в редакторе» больше нет, вместо него чтение из модели.

1. Документ семейства создаётся из шаблона целевой версии; категория, основа и точка вставки берутся из шаблона, а не назначаются «после».
2. Геометрия строится штатными телами по параметрическому каркасу; параметры и типоразмеры — через менеджер семейства, общие — по определениям с GUID.
3. Соединители, таблицы поиска и условная графика настраиваются до сохранения; таблица импортируется в семейство, внешний CSV сам по себе не работает.
4. Сохранение — в `.rfa` целевой версии. Дальше **обязательно**: повторно открыть сохранённый файл, перечитать содержимое, вставить в тестовый проект, сменить тип, перезагрузить.
5. Ошибка компиляции или отказ API — это диагностика, а не повод объявить успех: исправляй и повторяй, фиксируя, что именно изменилось.

Сборка пачкой (десятки семейств) не отменяет проверок: уровень приёмки объявляется для каждого семейства отдельно, а покрытие каталога считается по позициям, а не по числу файлов.

## Формулировки, которые проверяются

Критерий приёмки должен ловить дефект, а не описывать желаемое. «УГО присутствует» пропускает семейство, где линии привязаны к уровню детализации вместо параметра; «УГО управляется параметром, переключение испытано» — нет. Поэтому у каждого критерия есть обязательные машинно-проверяемые поля (`facts`): число типов, число заполненных, допуск и отклонение, протокол смены типа. `pass` без них не принимается. `partial` обязан назвать, чего не хватает, и что делать (`missing`, `next`), иначе это переодетый `pass`.

## Дисциплина вызова Revit

- Таймаут — **неизвестное состояние**, а не ошибка. Сначала запрос статуса операции по идентификатору, потом решение.
- Каждый вызов несёт идентификатор запроса; повтор с тем же идентификатором не выполняется второй раз, в том числе после перезапуска шлюза.
- Пока статус неизвестен, повторять операцию запрещено: вместо одного насоса получаются два.
- Бюджет времени на сборку сложного семейства — минуты, а не секунды по умолчанию.
- После любого повтора сравни количество и идентификаторы элементов до и после.

## Выход по объёму

Семейство/исправление либо конкретное замечание; версия Revit; **уровень приёмки** (L0–L8) и что именно проверено; ограничения и допущения. «Собрано», «готово», «рабочее» без уровня не выдаются: собранный файл — это L2, работоспособность в сети — L5, библиотечный выпуск — L8.

Приёмка семейства не подтверждает нормативное соответствие всей проектной системы.
