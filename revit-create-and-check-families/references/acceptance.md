# Приёмка семейства: уровни L0–L8 и акт

Общий язык для автора, проверяющего и заказчика. Любое утверждение о семействе несёт уровень: «проверено до L3». Слова «рабочее», «готово», «принято» без уровня запрещены.

**Проверяемость формулировки важнее её красоты.** «УГО присутствует» не ловит дефект: линии есть — вопросов нет. «УГО управляется параметром, переключение испытано» ловит. Поэтому у каждого критерия есть набор машинно-проверяемых полей `facts`; `pass` без них не принимается.

## Уровни

| Ур. | Что доказывает | Минимальное доказательство | Чего не доказывает |
|---|---|---|---|
| L0 | файл есть и не пуст | путь, размер, sha256 | что Revit его откроет |
| L1 | открывается в целевой версии без внешних ссылок | чтение из открытого документа | что внутри есть нужное |
| L2 | сущности на месте и связаны как заявлено | перечисление из модели | что значения заполнены |
| L3 | значения заполнены **по каждому типу** | чтение значений по всем типам | что числа совпали с каталогом |
| L4 | габариты в объявленном допуске; смена типа меняет размеры | чтение + кадры 3D/разреза | что работает в сети |
| L5 | работает в сети: подключился, расход/нагрузка дошли | протокол короткой сборки | как выглядит на плане |
| L6 | УГО читается на плане в масштабе; поворот и детализация верные | кадр плана проекта | что попадёт в спецификацию |
| L7 | спецификация и марка дают нужные графы, артикул, количества | выгрузка спецификации | что переживёт перезагрузку |
| L8 | перезагрузка и повторное открытие без потерь и размножения типов | протокол тестового проекта до/после | нормативного соответствия изделия |

## Критерии и обязательные факты

| id | Ур. | Критерий | `facts` на pass |
|---|---|---|---|
| О0 | L0 | Файл существует, не пуст, хеш записан | `bytes` |
| О1 | L1 | Открывается в целевой версии; ссылок и критичных предупреждений нет | `openedIn`, `externalRefs=0`, `criticalWarnings=0` |
| О2 | L2 | Категория и основа соответствуют назначению | `category`, `host` ∈ `wall\|floor\|ceiling\|face\|level\|free` |
| О3 | L2 | Состав и имена типоразмеров соответствуют каталогу | `types` = `typesExpected` |
| О4 | L2 | Параметры: общие по GUID, тип данных, тип/экземпляр | `sharedByGuid` = `sharedExpected`, `paramsTotal` |
| О5 | L2 | Соединители: количество, домен, форма/размер, положение, направление | `connectors` = `connectorsExpected`, `domain`, `flow` |
| О6 | L2 | **УГО управляется параметром**, а не только уровнем детализации | `ugoElements>0`, `ugoBoundParam`, `ugoToggleTested=true` |
| О7 | L2 | Таблица поиска импортирована; ключ уникален и в первой колонке | `tableRows` = `uniqueKeys`, `keyColumn="1"` |
| О8 | L2 | Нет импортированной геометрии | `importedGeometries=0` |
| О9 | L2 | Материалы назначены; изоляция задана параметрами | `materials>0`, `insulationParams` |
| О10 | L3 | Значения обязательных параметров у **каждого** типа | `filled` = `total` |
| О11 | L3 | Комментарий/описание типоразмера по шаблону | `commentFilled` = `types` |
| О12 | L4 | Габариты каждого типа в **объявленном** допуске | `toleranceMm`, `maxDeviationMm ≤ toleranceMm`, `dimsChecked>0` |
| О13 | L4 | **Смена типа меняет размеры**; опоры и точка вставки устойчивы | `protocol` ≥ 2 записи `{param,before,after}`, хоть один размер изменился |
| О14 | L5 | Испытание в сети: подключение, передача расхода/нагрузки, система | `system`, `flowForwarded=true` |
| О15 | L6 | УГО на плане 1:100 **и** 1:50; поворот; видимость по детализации | `scales` содержит `100` и `50`, `readable=true` |
| О16 | L7 | Спецификация: графы, единицы, группировка, итоги | `columns` = `columnsExpected` |
| О17 | L7 | Марка/обозначение на плане и в ведомости | `markVisible=true` |
| О18 | L8 | Перезагрузка: значения сохранены, типы не размножились | `typesBefore` = `typesAfter`, `valuesLost=0` |
| О19 | L8 | Производительность: вставка партии | `instances ≥ 50`, `seconds>0` |

Критерий, не относящийся к изделию (например таблица поиска у семейства с фиксированным рядом), получает `na` с `applicable=false`, причиной и подписью — и это видно в акте, а не растворяется в «частично».

## Статусы и вердикт

`pass` — совпало; нужны доказательство нужного вида **и** проходящие проверку `facts`.
`fail` — не совпало: **вердикт сразу rejected**.
`partial` — проверено частично; **обязательны `missing`** (что именно не проверено) **и `next`** (что делать). `partial` без плана — переодетый `pass`.
`na` — неприменимо, требует причины и подписи.
`pending` — не проверялось; ограничивает уровень.

- `verifiedLevel` — наибольший L, где все критерии до него `pass` или `na`.
- `accepted` — нет `fail` и `partial`, `pending` отсутствует, уровень ≥ 5 для одного семейства и ≥ 8 для библиотечного выпуска.
- `partial` — есть `partial`, нет `fail`. `rejected` — есть `fail`. `insufficient` — всё чисто, но уровень ниже требуемого.

Формулировка: **«Семейство X: собрано, проверено до L3; L4–L8 не проверялись»**.

## Правила доказательств

- `file` — L0; чтение из модели — L1+; кадр — L4+; протокол сборки в сети — L5; выгрузка спецификации — L7; протокол тестового проекта — L8.
- Журнал сборки, `verify.json`, строка «ошибок нет» — только вспомогательное, никогда единственное доказательство для L1+.
- Параметр, заполненный у активного типа и пустой у остальных, — это `fail` О10, а не `pass`.
- Доказательство указывается ссылкой: что открыли, что прочитали, чем снимали кадр.

## Акт

Минимальная форма (JSON или таблица в отчёте):

```json
{
  "family": { "id": "…", "revit": "2024", "scope": "family|library" },
  "source": { "vendor": "…", "article": "…", "revision": "…", "page": 61 },
  "claimedLevel": 3,
  "criteria": [
    { "id": "О10", "level": 3, "status": "pass",
      "expected": "ADSK_* у всех типов", "actual": "28 из 28",
      "facts": { "filled": 28, "total": 28 },
      "evidence": [ { "kind": "api-readback", "ref": "…" } ] },
    { "id": "О9", "level": 2, "status": "partial",
      "expected": "материалы и параметры изоляции", "actual": "материал есть",
      "missing": "параметры изоляции", "next": "добавить два параметра типа",
      "evidence": [ { "kind": "api-readback", "ref": "…" } ] }
  ],
  "assumptions": [ { "id": "A1", "text": "…", "why": "…" } ],
  "verdict": "insufficient", "checkedAt": "…", "checkedBy": "…"
}
```

Если расчёт вердикта не сходится с содержанием акта (заявлен L3, подтверждено L1) — акт недействителен.

## Дисциплина вызова Revit

- Таймаут — неизвестное состояние: сначала статус операции по идентификатору, потом решение.
- Идентификатор запроса обязателен и переживает перезапуск шлюза.
- Пока статус неизвестен, повтор запрещён: дубли элементов дешевле не становятся.
- Бюджет на сборку — минуты, а не 60 секунд по умолчанию.
- После повтора сравни количество и идентификаторы элементов до и после.

При недоступном Revit можно проверить описание и код, но нельзя заявлять, что RFA был открыт, перестроен или принят. Название «headless» доказательством не является.
