# Приёмка и обновление семейства

Для локальной ошибки выполняй только затронутые проверки. Для библиотечного выпуска:

1. Укажи файл, версию Revit/семейства, назначение, допустимые типы и ограничения. Сохрани исходник до изменения. Более новый RFA нельзя штатно сохранить назад в старый Revit; обмен геометрией не сохраняет параметрическое семейство. При нескольких целевых выпусках планируй исходник в самом раннем требуемом и проверяй обновлённые копии отдельно.
2. Редактор: все поставляемые типы, граничные значения и влияющие сочетания, основа, формулы, геометрия и порты. Не выдавай проверку одного номинального типа за проверку библиотеки.
3. Тестовый проект: вставка, замена типа, ориентации, основа, соединения при наличии, марки, ведомости, видимость и разрезание. Проверь сохранение/повторное открытие и перезагрузку с контролем существующих значений. Используй реальный шаблон-потребитель на копии, когда от него зависит результат.
4. Измеряй производительность на повторяемом сценарии, если менялась тяжёлая геометрия/вложенность или планируется массовая расстановка. Размер RFA один не описывает скорость проекта.
5. Проверку фиксируй как «файл/ревизия → случай → ожидаемое → фактическое → доказательство → статус». Для скриншота укажи вид, для автоматической проверки — среду, входы и журнал. Отсутствие предупреждений не заменяет проверку функции.
6. Выпускай только проверенный объём: RFA, нужный каталог/таблицы, краткое описание сложного поведения и перечень ограничений. Внешняя публикация не следует автоматически из поручения создать семейство.

При недоступном Revit можно проверить описание и код, но не заявлять, что RFA был открыт, перестроен или принят. Автоматизация через API/облачную среду подтверждается реальным журналом исполнения; название «headless» не заменяет этого доказательства.
